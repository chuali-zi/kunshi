# 2026-09-22 可玩房间美术与交互优化

本轮修改写入 `Assets/_Game/Scenes/Room_M1.unity`。目标是把已经交付的 Blender 资源真正用于 Unity 可玩房间，并使镜头、材质、照明和玩法状态相互一致。

## 参考与范围

- 官方视频：<https://www.youtube.com/watch?v=OHAjc-ayhus>。
- 本地 MV 角色参考：`art/reference/character/`。
- 房间 lookdev 对照：`art/previews/mv_20260911/blender_room.png`，也是用户指出与 Unity 实机不一致的房间图。
- 本轮内置浏览器能打开官方视频页面，但 YouTube 提示登录验证，未能重新播放完整视频。因此不把本轮工作描述为全片逐镜头验收。

## 已落地的美术修改

1. **软包扶手椅**：修正 Blender 源中 1024 个软包面的朝向，重新导出 v004，并保留原 FBX 资源 GUID。菱格现在能在 Unity 正常背面剔除下显示。位置恢复为 `(-1.8, 0.575, 1.5)`，椅后隐藏区域一起移动，重烘焙寻路。
2. **地毯**：修正 `MAT_Floor_DarkGreen_Rug` 的错误贴图，使用 `TEX_MAT_Fabric_Rug`。棕色编织毯与绿色地板重新分开。
3. **吊灯**：intact/broken 两态均升级为 v004；外侧灰绿漆面、内侧浅色和灯泡自发光使用各自材质槽，修复原升级脚本把灯罩两面都替换为黑色的问题。
4. **外套**：276 三角面的外套模型替换房间中的方块占位，包含袖口、翻领、褶皱和衣架。模型贴合东墙，碰撞体随模型尺寸调整。原有 Inspect 交互保留；没有把它描述为已经支持拾取或搜查。
5. **镜头**：固定电视机位的垂直 FOV 从 72° 改为约 57.38°，俯角改为约 0.912°，与房间 lookdev 的透视更接近。自由移动、交互和结局第一人称仍使用原有控制系统。
6. **照明**：灯具使用独立 PracticalEmitter，避免灯源留在安装根节点形成天花板过曝。启用实时软阴影，增加随真实灯同步的低成本环境补光，设置暖色环境底光。
7. **URP**：启用额外灯阴影与软阴影，2048 阴影图集中每个点灯面使用 512 分辨率；增加 SSAO 接触阴影、ACES、适度色彩调整和暗角。没有加入影响观察交互目标的景深或运动模糊。

统一入口为 **ConGame → Art → Upgrade Playable MV Room**。原 **Apply Abuku MV Art** 入口转发到该流程。新的升级流程修复现有主房间的展示配置，不重新覆盖整套交互接线；以后完整重建房间也会调用同一展示配置。

## 灯光与玩法联动

- `PracticalLightBounce` 同步实际灯的开关、层级启用状态、颜色与强度。实际灯断电或破坏后，属于它的补光也会关闭。
- `BreakableLightPresenter` 使用材质属性块同步灯泡及碎片的自发光。关灯、断线、破坏时不再留下白色发光灯泡；盖灯变暗红后自发光也同步变化。
- 保留原设计区分：可恢复暗场允许神秘人接近并重新打开未损坏、线缆仍连接的台灯；双灯破坏进入 PersistentBlack，不能把破灯重新打开。盖灯的 Draped 状态不冒充 PersistentBlack。

## 本轮代码修复

- `CounterplayNextOutcomeBridge` 检查当前循环 epoch 和来源 outcome，拒绝上一轮遗留的衔接请求；保留合法 D08/D21 到后续反击的衔接。
- 近战命中点计算对非凸 MeshCollider 使用包围盒最近点，避免调用 Unity 不支持的 `Collider.ClosestPoint` 路径。
- 近战固定视角的顶灯命中体使用真实高度：`verticalHalfHeight = Mathf.Max(hitboxHalfHeight, reach)`。这样命中体上缘会覆盖可见顶灯网格，修复了“挥击看得到但打不到”的实际交互问题。
- 陷阱放置位在另一种陷阱已经生效时拒绝放置，物件留在原位；修复“放置成功但事实没有切换”的静默失败。
- 旧测试同步现行规则：推倒书柜需要等待演出完成；主动拉被需要接触和玩家上下文；D21 必须等掉落语义事件后开放拾取窗口；结局等待时间按实际配置计算。

## 验证

结果和 Unity Game View 截图保存在 `Logs/mv_optimization_20260922/`。验证过程需要区分一次干净场景全量回归和受影响套件复测：

- `playmode_clean.json` 记录的第一次干净场景全量结果是 **120 项、117 通过、3 失败**。失败项分别暴露了 D21 照射后的自然完成时序、近战顶灯命中体高度，以及一个带浮点显示相同但严格比较失败的攀爬位置断言；不能把这次结果写成全量通过。
- 近战交互套件 `interaction_final.json` 复测 **17/17 通过**；D21 等反击套件 `counterplay_final.json` 复测 **5/5 通过**。
- `test_latest_results.json` 是“干净全量结果加两个受影响套件复测”的每项最新结果汇总。按这个 latest-per-test 汇总，**120/120 项最新结果通过**；这不是声称某一次单独的全量 120 项运行就通过。

实际 Play 检查记录如下：

- 使用 Unity InputSystem 长按 `E` 约 `0.65 s` 抓取 Blanket，确认 `HeldMovementMultiplier = 0.5`。
- 长按 `S` 约 `0.9 s`，确认被拿着的物件贴地跟随，而不是被当作投掷物释放。
- 使用 `TryPlaceHeld` 将被子放入台灯覆盖槽，确认放置成功；台灯、`TableBounce` 补光和灯泡 emission 同步变为暗红；顶灯仍亮时 `RoomLight = Lit`。
- `10_room_final.png` 是正常游戏主镜头；`12_lamp_draped.png` 和 `13_coat_and_mirror.png` 是运行时检查视角，用于查看灯罩垂落、外套和镜面状态，检查视角隐藏玩家以免遮挡。
- 通过公共受击入口破坏两盏灯后，实机事实为 `PersistentBlack`，两个 PracticalEmitter 与三个关联补光全部关闭；截图为 `14_persistent_black.png`，状态记录为 `persistent_black_state.json`。截图保留固定主镜头，玩家沿用检查时隐藏状态，并冻结倒计时。
- 检查结束后退出 Play Mode，恢复检查前的 `save.json` 和备份存档。Unity 停留于已保存的 `Room_M1` 编辑场景，主相机 FOV 为 `57.3835`，无未保存场景改动，控制台错误和警告均为 0。
- 这些是定向的运行时交互和视觉检查，不冒充从头到尾的自然通关，也不替代完整的 D01–D22 自然路线验收。

截图会明确区分正常主镜头和用于检查侧墙/状态的运行时检查镜头。照明与互动检查允许编辑器定位角色、冻结倒计时或调用公共玩法入口；不据此宣称完整自然通关所有 D01–D22 路线。

## 仍有的视觉差距

角色脸部、衣物轮廓和动作仍是现有版本，与 MV 的逐镜头表演存在差距。被子使用多状态网格和地面拖拽，没有实现真实 Cloth 模拟。房间灯光使用实时阴影、屏幕空间遮蔽和随灯补光，不能等同于 Blender Cycles 的路径追踪间接光。
