# 2026-10-13：D21 真实掉落与手电扫光

本轮针对 `game_flow_script.md` D21 第 2 步的明确差距继续推进：神秘人倒地时主枪、手电脱手飞出；手电落地亮着并扫转，玩家自行决定拿哪个物件。保留原目标，当前仍不能据此判定已经接近完整 MV 表现。

## 实现

- `StolenLootDropController` 为手枪和手电分别消费对应掉落事件，同一循环的重复事件不会再发射或瞬移物件；两个掉落事件完成后才开放选择窗口。发射位置来自人物手枪与枪轨手电，沿入室方向偏移 0.25 米以避开身体，并避免落地动画手骨低于地板时把物件生成进地板。
- `StatefulWorldItem.TossIntoWorld` 将未持有的物件交给已有刚体、重力和连续碰撞路径，带短程速度与旋转。掉落时短暂忽略角色碰撞，0.2 秒后恢复；普通玩家投掷沿用其原来一个 FixedUpdate 的恢复时间。脚本掉落不消费玩家投掷命中或刺激事件，也不能抢走手中的物件。循环复位沿用原变换、刚体和碰撞恢复流程。
- QTE 脱身时先真实解除玩家持有，再对掉落手电施加小推力与旋转，仍要求玩家手动再次拾取。
- `DroppedFlashlightPresenter` 驱动独立聚光灯。飞行和滚动时光束跟随物件；拿到手中后与现有 Use 射线的胸前起点、玩家瞄准方向一致。扫光本身不会触发眩光成功、照镜分支或完成反制。复位时熄灭并清除旧轮状态。
- `RoomDesignGapInstaller` 在房间初始化时接入发射点和掉落聚光灯；本轮没有手写场景、Prefab 或 `.meta`。
