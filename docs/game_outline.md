## 一、游戏概述

| 项目 | 内容 |
|---|---|
| 类型 | 第三人称固定机位 · 死亡循环 · 试错沙盒解密 |
| 引擎 | Unity（C#，URP 渲染管线） |
| 时长 | 小品级，1~2 小时通关 |
| 场景 | 单一房间（约 6m × 5m 起居室） |
| 视角 | 全程固定机位（机位 = 房间内电视机的位置），结局切换第一人称 |
| UI | **零 UI**：无血条、无提示、无任务栏、无交互图标，所有信息靠画面演出传递 |
| 基调 | 压抑、诡异、留白。不解释神秘人是谁、循环为什么存在 |

**一句话卖点**：你在一个必死的房间里用尽一切办法求生，直到你意识到——杀出去的唯一出口，是砸碎正在"看着你"的那台电视机。

**设计支柱（三条，所有决策以此为准）：**
1. **死亡即语言**——失败不是惩罚，每一种死法都是一段演出、一条信息。玩家的进度感来自"我又发现了一种新死法"。
2. **万物可动**——凡是画面里像能碰的东西就能碰。流程脚本中出现的每个物品、每个动作，玩家都必须真的能做到（硬性验收标准）。
3. **镜头即真相**——固定机位不是技术限制，而是叙事本体：镜头就是电视机，电视机就是出口。所有引导都围绕"让玩家注意到镜头本身"来做。

## 二、核心循环设计

```
苏醒（沙发上，固定起点）
   │  自由行动期：20~45 秒（时长见下文"神秘人入场计时"）
   ▼
玩家自由交互（拾取/搬运/躲藏/布置陷阱/破坏……全部交互从第 1 个循环起全开放）
   │
   ▼
神秘人破门而入
   │
   ▼
玩家策略 vs 神秘人反制（见反制表）
   │
   ▼
玩家死亡 ──► 无缝硬切 ──► 回到苏醒点（无读条、无黑屏渐变、无死亡结算画面）
```

**循环规则：**
- 死亡瞬间直接硬切（1 帧内切换）回沙发苏醒姿势，模拟"录像带倒带"的突兀感。可伴随一声极短的电流杂音。
- 房间状态完全重置：被打坏的灯复原、移动过的家具归位、神秘人消失。
- **唯一跨循环保留的状态**：玩家的"摸瞎经验"计数（见光照系统）与循环计数（用于演出微差异，如电视机雪花噪点逐渐变强）。
- 神秘人入场计时：默认苏醒后 30 秒破门。玩家发出巨大声响（砸墙、砸窗、打碎花瓶）会提前至声响后 8 秒——"他在门外听着"。玩家完全静止不动则延长到 45 秒。这个弹性让玩家感到神秘人"有反应"，而非闹钟。

**通关路径（唯一）**：对电视机（= 镜头）使用棒球棍或椅子等重物攻击 → 触发结局序列（详见流程脚本 E 段）。

## 三、六大系统设计

### 3.1 固定机位相机系统

**机制描述**
- 主相机固定在电视机屏幕位置，朝向房间中央，略带监控摄像头式的轻微俯角。
- 画面持续叠加极轻的 CRT 效果（扫描线 + 暗角 + 偶发一帧噪点），暗示"你在看一台电视"。
- 玩家走到镜头近处时，角色可以"挡住镜头"，此时画面大面积被角色身体遮挡——这是合法且刻意的，是结局的引导之一。
- 结局打碎电视机后，相机切换为第一人称（挂在主角头部骨骼上）。

**Unity 实现要点**
- Cinemachine：`CinemachineCamera`（固定 Virtual Camera，不跟随、不旋转）作为常规机位；第一人称机位为第二个 Virtual Camera，结局时用 `CinemachineBrain` 硬切（Blend 时长 0）。
- CRT 效果用 URP Full Screen Pass / 自定义后处理 Shader，强度暴露参数给 LoopManager（随循环数微调噪点强度）。
- 角色控制器需按"镜头相对方向"输入移动（类似早期生化危机的固定机位移动方案，推荐用相机相对坐标而非坦克式操作）。

**验收标准**
- [ ] 全程（除结局）相机位置与朝向零变化。
- [ ] 死亡切回时相机无任何过渡动画。
- [ ] 角色可走到距镜头 0.5m 内并遮挡画面，不发生穿模或相机裁剪异常（near clip 需调小）。
- [ ] 结局第一人称切换在 1 帧内完成。

### 3.2 交互系统

**机制描述**
- 玩家角色有一套统一的交互动词集，任何可交互物品声明自己支持哪些动词：

| 动词 | 说明 | 默认按键（手柄/键鼠） |
|---|---|---|
| 检查 Inspect | 走近注视，角色做出低头/伸手细看动作（无文字弹窗，纯动画） | 靠近自动 |
| 拾取 PickUp | 单手可持物品拿在手上 | E / X |
| 使用 Use | 对手持物或环境物执行其主行为（开抽屉、按遥控器、拉被子） | E / X |
| 投掷 Throw | 将手持物掷向瞄准方向 | 右键 / RT |
| 挥击 Swing | 手持钝器时的近战攻击（可打人、打灯、打电视机、砸墙） | 左键 / RT |
| 推拉搬运 Carry | 双手搬起大件（椅子、抽屉柜），移动速度减半，可放下或掷出 | 长按 E / X |
| 躲藏 Hide | 对掩体类物品进入躲藏姿态（蹲沙发后、钻被子、钻床底） | C / B |
| 放置布置 Place | 将手持物放到指定位置（被子铺到门口、椅子顶到门把手下） | 靠近目标点按 E |

- 物品存在三态：**放置态**（在场景原位或被移动后的位置）、**手持态**、**飞行态**（被投掷，纯物理）。
- **无高亮、无图标**：可交互性靠物品本身的显眼摆放与玩家试错发现。但角色靠近可交互物时，头部有 IK 注视（角色会"看"它），这是唯一的软提示。
- 所有交互从第 1 个循环起全部可用，无任何解锁门槛（纯试错沙盒原则）。

**Unity 实现要点**
- 接口 `IInteractable`：`SupportedVerbs`（Flags 枚举）、`OnInteract(Verb, PlayerContext)`、`GetInteractAnchor()`（角色对齐点）。
- 场景物品挂 `InteractableItem` 基类组件 + 各自的具体行为组件（如 `Blanket`, `Chair`, `TVSet`），行为组件只关心自己，互相不引用。
- 检测：角色胸前一个 `OverlapSphere`（半径 1.2m）+ 朝向点积筛选最优目标。
- 头部注视用 Animation Rigging 的 Multi-Aim Constraint。
- 投掷/搬运用 Rigidbody 切换 isKinematic；手持时物品 attach 到手部骨骼 socket。

**验收标准**
- [ ] 流程脚本中的每一个动作可实际执行（对照 [game_flow_script.md](game_flow_script.md) 的死法表逐条打勾）。
- [ ] 任意物品在三态间切换无物理爆炸、无穿地。
- [ ] 新增一个可交互物品无需修改任何既有代码（只新增组件 + 场景摆放）。

### 3.3 循环管理系统（LoopManager）

**机制描述**
- 记录：循环序号、本循环玩家行为标签（如 `hid_behind_sofa`、`broke_light`、`ambushed_at_door`）、累计摸瞎经验。
- 死亡时**不重载场景**，而是把所有已注册的可变对象回滚到快照状态（位置、旋转、完好度、灯光开关），保证硬切无缝、无加载。
- 行为标签供两处消费：① 神秘人 AI 选择反制演出的细分版本；② 演出微差异（循环数高时电视噪点更强、主角苏醒动作从惊恐渐变为麻木）。

**Unity 实现要点**
- `ILoopResettable` 接口：`CaptureInitialState()`（游戏启动时调用一次）、`ResetToInitialState()`（每次死亡调用）。所有可变物品实现它并向 LoopManager 注册。
- 死亡流程：`OnPlayerKilled` 事件 → 冻结输入 → 同一帧内回滚全部对象 + 重置玩家到沙发 + 播放苏醒动画第 0 帧 → 恢复输入。
- 行为标签用 `HashSet<string>`，每循环清空，跨循环统计存独立字典。
- 存档：只需序列化循环计数与摸瞎经验（PlayerPrefs 或 JSON 均可，数据量极小）。

**验收标准**
- [ ] 连续死亡 50 次无内存增长、无状态残留（上一循环搬动的椅子必须回原位）。
- [ ] 死亡到可再操作间隔 ≤ 0.5 秒。

### 3.4 神秘人 AI

**机制描述**
- 神秘人不是自由 AI，而是**"反制表驱动的演员"**：破门后感知玩家状态，从反制表中匹配一条对应的击杀演出并执行。反制表全表见 [game_flow_script.md](game_flow_script.md) 附录 A。
- 感知规则（用于匹配反制条目）：
  - **视觉**：进门后 120° 视锥，明亮环境下全屋可见；黑暗中视距降为 1.5m，但会立即掏出枪挂战术手电（光锥内恢复可见）。
  - **听觉**：全屋可闻。躲藏中的玩家若移动会发出声响、暴露位置（对应"射击被子"死法）。
  - **触觉/绊倒**：脚下有被子/地毯被拉拽时触发绊倒演出（唯一能让他倒地的方式）。
- 性格准则（演出统一性）：冷静、零台词、不跑动（快步走）、枪法必中、对投掷物侧身闪避、对投降者照杀不误。他永远不主动破坏物品，除了射击玩家藏身的掩体。
- 特殊道具：风衣内有第二把手枪（仅在玩家夺枪成功的分支中掏出）；主手枪挂战术手电（仅在黑暗分支中开启）。

**Unity 实现要点**
- 不必上行为树插件，一个 `KillerDirector` 状态机足够：`Entering → Perceiving → CounterPlay(表条目ID) → Executing → Idle`。每条反制是一个 `ScriptableObject`（条件谓词 + Timeline 演出资产引用）。
- 击杀演出用 Timeline + Animation，涉及与玩家的双人交互动作（搏斗、拉扯）用配对动画（match target 对齐）。
- 感知条件写成可组合的谓词（`IsPlayerHidden`, `IsRoomDark`, `IsHoldingWeapon`, `TripTrapArmed`…），反制表按优先级从上到下匹配第一条。

**验收标准**
- [ ] 反制表中每一条都能被稳定触发且演出对位正确（双人动作不穿模、不滑步）。
- [ ] 任何未被表覆盖的玩家状态落入"默认击杀"兜底条目，绝不出现神秘人卡住发呆。
- [ ] 新增一种死法 = 新增一个 ScriptableObject 条目 + 一段 Timeline，零代码改动核心状态机。

### 3.5 光照与黑暗系统

**机制描述**
- 房间两个光源：**顶灯**（主光）与**台灯**（副光）。都可被挥击打坏。只坏顶灯 → 昏暗；两个全坏 → 近乎全黑。
- **摸瞎经验**（跨循环成长，对应原始脚本第 10~11 条）：玩家每在全黑状态下存活满 5 秒，经验 +1（上限 5 级）。每级让全黑环境的环境光亮度提升一小档（从伸手不见五指 → 能辨认家具轮廓）。这是全游戏唯一的数值成长，且无任何 UI 表现——玩家只会感到"我好像越来越适应黑暗了"。
- 神秘人在黑暗中会开启枪挂战术手电：一个锐利的可见光锥，既是威胁（照到即死）也是场景中唯一动态光源，构成黑暗回合的核心博弈画面。
- 手电筒（从神秘人处抢得或搏斗中掉落后捡起）：玩家可持握照明与照射神秘人（对应原始脚本第 13 条演出）。

**Unity 实现要点**
- URP 实时光。顶灯/台灯是带 `Breakable` 组件的 Point/Spot Light，被挥击后播放爆裂粒子 + 熄灭 + 音效。
- 全黑环境亮度 = 场景 Ambient 强度参数，由 LoopManager 按摸瞎经验等级设置（0.002 → 0.02 五档）。
- 战术手电 = 神秘人手部 socket 上的 Spotlight + 体积光（URP 需用假体积光面片或 Volumetric 插件）。
- "照到即死"判定：手电光锥用一个跟随的碰撞锥体触发器实现，不做逐像素光照检测。

**验收标准**
- [ ] 灯可被棒球棍与投掷物打坏，破坏后本循环内不复亮，死亡重置后复原。
- [ ] 全黑 0 级时玩家确实几乎不可视（截图直方图验证），5 级时可辨轮廓但仍不可辨细节。
- [ ] 手电光锥照到玩家 0.8 秒内触发击杀演出。

### 3.6 搏斗与夺枪系统

**机制描述**
- 近身搏斗（偷袭命中后、绊倒后扑上去）进入**脚本化拉扯演出 + 简单输入对抗**：屏幕无提示，玩家连打交互键可以"赢下"当前回合的拉扯（把枪打飞、抢到手电），但**演出的最终结局按脚本注定失败**——神秘人总有下一手（挣脱、备用枪）。除结局序列外，搏斗永远通向死亡。
- 设计意图：让玩家在拉扯中产生"差一点就赢了"的错觉，驱动重试；同时用"备用枪"这类反制明确传达"正面对抗此路不通"，把玩家推向别的思路。
- 夺到的手枪：可以开枪，但弹仓只剩 1 发且必然打偏/被闪身（演出化处理），随后被备用枪反杀——枪不是答案。

**Unity 实现要点**
- 搏斗 = Timeline 演出 + 若干"对抗窗口"标记点：窗口内统计连打次数决定播放 A 分支（玩家小胜，进入下一窗口）或 B 分支（直接被杀）。
- 双人动画对齐用 Match Target / Animation Rigging；枪、手电作为可掉落道具在演出关键帧从 socket 分离并交给物理。
- 玩家开枪：简单射线 + 神秘人闪避动画硬直，不做真实弹道。

**验收标准**
- [ ] 连打赢下全部窗口后，演出仍以脚本化失败收尾（备用枪）。
- [ ] 掉落的枪/手电落地后可被双方拾取逻辑正确（玩家先到先得，神秘人若先到直接进入处决）。

## 四、拓展性要求（硬性架构约束）

新增内容的成本必须满足：

| 要拓展的东西 | 允许的改动范围 |
|---|---|
| 新可交互物品 | 新增预制体（挂 `InteractableItem` + 自身行为组件）+ 摆进场景。零核心代码改动 |
| 新死法 | 新增一条反制表 ScriptableObject + 一段 Timeline 演出。零状态机改动 |
| 新交互动词 | 允许扩展 Verb 枚举 + 角色动画，一处集中改动 |
| 新房间（续作/加量） | LoopManager、相机、交互系统均不与"本房间"耦合，机位与物品清单全部场景内配置 |

**禁止**：任何物品行为脚本直接引用另一个具体物品类；任何死法逻辑写死在 KillerDirector 状态机里。
